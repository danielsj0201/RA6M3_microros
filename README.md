# RA6M3_microros

micro-ROS (ROS 2 Humble) client running on a Renesas **RA6M3** (R7FA6M3AH3CFC, Arm Cortex-M4F) over Ethernet.
The firmware runs FreeRTOS + FreeRTOS+TCP with a custom UDP transport for Micro XRCE-DDS, and publishes a
`std_msgs/msg/Int32` counter to a micro-ROS Agent running on an NXP S32G (ROS 2 Humble).

Built with Renesas e² studio and FSP 3.5.0. The micro-ROS library is shipped as a prebuilt static archive
(`microros_core/libmicroros.a`) configured for a custom transport.

## What the firmware does

`src/new_thread0_entry.c` is the whole application. On boot it:

1. Opens SCI UART0 (115200 8N1) for optional debug output.
2. Brings up FreeRTOS+TCP with a static IP and a fixed MAC address, then **blocks until the link is up**
   (`vApplicationIPNetworkEventHook` sets `xNetworkUp`).
3. Installs FreeRTOS-heap-backed allocators into `rcutils` (`microros_allocators.c`).
4. Registers the custom UDP transport (`rmw_uros_set_custom_transport`, framing disabled) with the Agent
   address as the transport argument.
5. Pings the Agent every second until it answers (`rmw_uros_ping_agent`).
6. Creates node `ra6m3_node` and a publisher on topic `ra6m3_counter` (`std_msgs/msg/Int32`, default QoS).
7. Publishes an incrementing counter once per second, forever.

Any initialization failure ends in `error_loop()`, which prints the reason over UART and parks the task.

## Network configuration

All addresses are static and hard-coded.

| Parameter | Value | Where to change |
| --- | --- | --- |
| Board IP | `192.168.0.10/24` | `ucIPAddress` / `ucNetMask` in `src/new_thread0_entry.c` |
| Gateway / DNS | `192.168.0.1` / `8.8.8.8` | `ucGatewayAddress` / `ucDNSServerAddress` in `src/new_thread0_entry.c` |
| Board MAC | `00:11:22:33:44:55` | `ucMACAddress` in `src/new_thread0_entry.c` **and** `g_ether0` MAC in FSP config |
| Agent IP / port | `192.168.0.50` / `5000` (UDP) | `AGENT_IP` / `AGENT_PORT` in `src/new_thread0_entry.c` |
| Hostname | `ra6m3-microros` | `pcApplicationHostnameHook()` |

The Agent host and the board must be on the same L2 segment (no routing is required, but the gateway must be
reachable for FreeRTOS+TCP to consider the interface fully configured). DHCP is compiled out
(`ipconfigUSE_DHCP 0` in `ra_cfg/aws/FreeRTOSIPConfig.h`).

## Build and flash

1. Clone the repository and import it into e² studio (**File → Import → Existing Projects into Workspace**).
2. Open `configuration.xml` and click **Generate Project Content** so `ra/` and `ra_gen/` match FSP 3.5.0.
3. Build (`Project → Build Project`). The link step pulls `microros_core/libmicroros.a`; the include path
   `microros_core/include` is already set in `.cproject`.
4. Connect the E2/E2 Lite debugger and run the `RA6_microdds_test Debug_Flat` launch configuration to flash
   and start the firmware.

The single FreeRTOS task (`new_thread0`) is created by FSP-generated code in `ra_gen/new_thread0.c` with a
16000-byte stack.

## Running the demo

On the Agent host (S32G or any Linux machine with ROS 2 Humble and `micro_ros_agent`):

```bash
ros2 run micro_ros_agent micro_ros_agent udp4 --port 5000 -v6
```

Power or reset the board. Once the link is up and the Agent responds to the ping, the node appears in the
ROS 2 graph:

```bash
ros2 node list          # /ra6m3_node
ros2 topic list         # /ra6m3_counter
ros2 topic echo /ra6m3_counter
# data: 0
# data: 1
# ...
```

If the Agent is started after the board, the board keeps pinging once per second and connects automatically.

## Implementation notes

**Custom transport (`udp_transport_freeRTOS.c`).** The four Micro XRCE-DDS transport callbacks map directly
onto FreeRTOS+TCP UDP sockets: `open` creates a `FREERTOS_SOCK_DGRAM` socket, `write` uses `FreeRTOS_sendto`
with the Agent address taken from `transport->args`, `read` sets `FREERTOS_SO_RCVTIMEO` to the timeout requested
by the client library on every call and then blocks in `FreeRTOS_recvfrom`, and `close` shuts the socket down.
The socket is never explicitly bound; the FSP option *Enable FreeRTOS_sendto() without calling Bind* is turned on
for this reason. Transport MTU is 512 bytes (`UXR_CONFIG_CUSTOM_TRANSPORT_MTU`).

**Network bring-up ordering.** `FreeRTOS_IPInit()` is called from the application task, not from
`transport_open`, and the task waits for the network-up event before touching micro-ROS. An earlier version
(kept commented out in `udp_transport_freeRTOS.c`) initialised the stack inside `transport_open` and derived the
MAC from the BSP unique ID; without the explicit link wait the first ping to the Agent was sent before the
interface was usable.

**Time source (`microros_time.c`).** `clock_gettime()` reads AGT channel 0 configured as a 65536-count periodic
timer on PCLKB (≈1.09 ms period). The ISR callback `micro_ros_timer_cb` counts rollovers; the current time is
`rollovers × period + (period − counter) × ns_per_tick`. This is the reference used by rmw for session timeouts
and by `rmw_uros_ping_agent`.

**Memory.** `microros_allocators.h` defines `MICROROS_FREERTOS_ALLOCATORS`, so all rcutils allocations go to the
FreeRTOS Heap 4 (128 KiB). `pvPortRealloc` is implemented locally by reading the Heap 4 block header, and a
`pvPortCalloc` shim is provided because the FSP FreeRTOS port does not export one. The rmw configuration baked
into `libmicroros.a` allows 1 node, 10 publishers, 5 subscriptions, 1 service, 1 client, stream history 4
(input/output buffers of 4 × 512 bytes). The FreeRTOS+TCP IP task runs at `configMAX_PRIORITIES - 2`.

**Debug output.** UART prints are wired (`uart_print` with a TX-complete callback) but commented out in the
main flow to keep the loop quiet; uncomment the `uart_print` calls in `new_thread0_entry.c` to trace bring-up.

## Known limitations and TODO

- Static IP and a fixed MAC (`00:11:22:33:44:55`) are hard-coded. The BSP-unique-ID-derived MAC logic exists but
  is commented out; re-enable it or move the addresses to the FSP configuration if more than one board shares
  a network.
- Only a single publisher is exercised. No subscriber, executor, or service is created, so the rmw limits above
  are far from being stressed.
- `libmicroros.a` is a prebuilt artifact; the colcon/meta configuration used to build it is not in this
  repository. Rebuild it with the micro-ROS build system if the transport type or entity limits need to change.
- `.gitignore` is saved as UTF-16, which Git does not parse, so `Debug/` (build output) is currently tracked.
  Re-save the file as UTF-8 and run `git rm -r --cached Debug` to fix.
- No hard-fault handlers are installed (a `BKPT`-based set is present but commented out).

## Related work

The client/agent split used here — RA6M3 running the Micro XRCE-DDS client, S32G running the Agent and the
ROS 2 graph — is the testbed configuration studied in:

> S. J. Shin *et al.*, "Analysis of Runtime Client-Join Disturbance in a Micro XRCE-DDS Client-Agent
> Architecture," *Proc. ICUFN 2026*, Milan, Italy, July 2026. (Best Paper Award)

The transport, time, and allocator sources follow the structure of the official
[micro-ROS Renesas e² studio component](https://github.com/micro-ROS/micro_ros_renesas2estudio_component).
